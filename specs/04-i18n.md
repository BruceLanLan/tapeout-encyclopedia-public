# Multilingual contribution (i18n)

## Principles

1. **Same slug, parallel locales** — `content/entries/zh/nand.md` and `content/entries/en/nand.md` share `id` / `slug`.
2. **No language is a second-class dump** — English is not a translation of Chinese-only truth; both should cite sources.
3. **Partial coverage is OK** — publish `zh` first, open an issue for `en` (or the reverse).
4. **Do not machine-translate without review** — agent drafts must set `status: draft` and list the agent under `agents`.
5. **Preserve technical tokens** — `NAND`, `LATCH`, `BEM`, `PoD`, `tape://`, contract names stay in Latin script unless an established local term exists (then put Latin in `aliases`).

## Adding a new locale

1. Create `content/entries/<locale>/`.
2. Add locale metadata in `content/locales.json`.
3. Translate at least one seed entry + update graph `label.<locale>` where possible.
4. Open a PR titled `i18n(<locale>): …`.

## Translation PR checklist

- [ ] Frontmatter `locale` matches directory
- [ ] `id` / `slug` unchanged
- [ ] `sources` preserved or improved (do not drop citations)
- [ ] No yield / price promises added
- [ ] Native speaker or bilingual reviewer requested
